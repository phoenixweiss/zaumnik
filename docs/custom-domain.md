# Подключение zaumnik.phoenixweiss.me

Проект поддерживает два варианта сборки на одном GitHub Pages-хостинге:

| Команда             | Адрес сайта                               | Путь        |
| ------------------- | ----------------------------------------- | ----------- |
| `yarn build`        | `https://phoenixweiss.github.io/zaumnik/` | `/zaumnik/` |
| `yarn build:domain` | `https://zaumnik.phoenixweiss.me/`        | `/`         |

Настройки находятся в `config/site.js`. Сборка задаёт пути ресурсов, favicon,
canonical и Open Graph/Twitter. Навигация использует hash-маршруты, например
`/#/word/канон`; копирование ссылки сохраняет адрес текущего сайта.

Режим `domain` используется в Pages workflow и проверке перед выпуском через
Bumpster. Его локальная сборка не подключает домен и не публикует сайт.
Независимого зеркала и автоматического
переключения нет; стандартный GitHub URL после подключения custom domain может
перенаправлять на личный домен.

## Проверка перед подключением

```sh
yarn quality
yarn quality:domain
```

Команды по очереди собирают `dist` и проверяют каждый вариант в браузере.
Они проверяют метаданные, ресурсы, открытие статей по прямым ссылкам после
перезагрузки, поиск, навигацию и копирование ссылок. Последняя команда оставляет
в `dist` сборку выбранного режима.

## Подключение и публикация

Следующие действия выполняются отдельно после согласования:

1. Проверить доступ администратора репозитория и управление DNS зоны
   `phoenixweiss.me`, отсутствие конфликтующих записей поддомена.
2. Проверить, что шаг сборки в `.github/workflows/pages.yml` использует
   `yarn quality:domain`. Проверка перед Bumpster запускает ту же команду.
   Сохранить проверку опубликованного релиза, права и публикацию по тегу.
   Обычный CI проверяет вариант `/zaumnik/`.
3. До изменения DNS подтвердить владение доменом в GitHub, если это ещё не
   сделано, и задать `zaumnik.phoenixweiss.me` в Settings → Pages → Custom domain.
4. Создать DNS-запись `CNAME` для `zaumnik` со значением
   `phoenixweiss.github.io` — без схемы и без `/zaumnik/`.
5. Выпустить подготовленный релиз через Bumpster и дождаться Pages deployment.
   Согласовать окно переключения: смена адреса Pages и публикация артефакта
   не являются одной атомарной операцией, возможен временный перерыв.
6. Дождаться проверки DNS и выпуска сертификата, включить Enforce HTTPS,
   проверить публичный сайт, ресурсы, метаданные, поиск и прямую ссылку на слово.

При публикации через GitHub Actions файл `CNAME` не требуется: домен задаётся
в настройках Pages. Запись в DNS не заменяет эту настройку.

## Публичные ссылки при переключении

- Website в GitHub About сейчас указывает на
  `https://phoenixweiss.github.io/zaumnik/`. После проверки нового домена заменить
  его на `https://zaumnik.phoenixweiss.me/`.
- В README добавить ссылку на действующий поддомен после подключения. До этого
  режим `domain` описывается как вариант сборки, а не как работающий сайт.
- Canonical, Open Graph и Twitter уже выбираются по режиму сборки; дополнительные
  ручные замены в HTML не нужны.
- В `package.json` поля `homepage` нет. Отдельной ссылки на сайт в странице
  «О проекте» нет; ссылки на GitHub и личный сайт автора остаются прежними.
- В проекте нет manifest, sitemap и robots.txt; добавлять их ради подключения
  домена не требуется.

## Ручной возврат

Если личный домен недоступен, убрать custom domain из настроек Pages и выпустить
сборку для `/zaumnik/`, вернув шаг сборки workflow к `yarn quality`. Проверить
GitHub URL без перенаправления, ресурсы и прямые ссылки; браузер может сохранять
прежний редирект в кеше. Одного переключения DNS для возврата недостаточно.
